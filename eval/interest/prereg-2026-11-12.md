# 관심사 질의 1단계 — 검색 전략 비교 사전 등록 (2026-11-12, HYO-187)

> 결과 0건 시점에 등록한다. 순위도 판정도 아직 돌리지 않았다. 이 커밋 뒤로 바꾸는 것은 지우지 않고 `변경 (날짜, 이유)`로 남긴다 (규율 7).
> 관련: `docs/design/retrieval-arena.md`(전략 고정값) · `docs/design/query-topk.md`(질의별 목록) · 코드 `eval/interest/run_interest.py`

## 1. 질문

**레인 B 관심사 순위가 놓치지 않으려면 어떤 검색 방법을 써야 하나?**

- 지금 관심사 순위는 키워드 매칭(`pipeline/keyword_match.py`)이다. W46을 보면 2,433건 중 271건에 점수를 매긴다. 그런데 그 결과가 목록에도 detect에도 가지 않는다.
- 모델이 아닌 새 기술(검색 기법, 그래프 도구, 에이전트 런타임, eval 프레임워크)이 들어올 길은 이것뿐이다.
- 계획은 2단계다. 이 등록은 **1단계(검색)만** 잰다.
  - 1단계: 검색으로 넓게 모은다(놓치지 않기).
  - 2단계: LLM이 "실험해 볼 만한가"를 판정한다.
- Arena B 유형(의미 검색)에서는 BM25가 0.058, KURE-Sparse와 리랭커가 약 0.34였다. 다만 BM25가 진 주된 이유는 한국어 질의와 영어 문서가 엇갈려서였다. 이번에는 영어 질의를 주로 쓴다.

## 2. 코퍼스

- 대상: `corpus@2026-W46`(radar-snapshots `2026-W46/items.jsonl`)의 **레인 B 후보 전부**.
  - 뽑는 법은 제품과 같다: `pipeline.profile_filter.read_items` 다음에 `pipeline.lanes.split_lanes`.
- 문서로 바꾸는 법은 Arena와 같다: `arena.corpus._item_to_doc`(HTML 출처는 텍스트로 바꾼다).
- 청크는 `chunk-policy@v1`(bge-m3 토크나이저 512)로 자른다. 문서 순위는 문서마다 최고 청크로 매긴다(`harness.rollup_chunks`).
- 코퍼스 버전 이름은 `c-laneb@2026-W46`이다. 임베딩 캐시와 ES 색인 이름에 쓴다.

## 3. 질의 (`eval/interest/queries-w46.jsonl`, 28개)

- 관심사는 `radar-profile.yaml` v1(adr 92aa93a)의 active 14개다. W46 실행이 쓴 해석본 그대로를 `eval/interest/profile-w46.json`에 복사했다.
- **영어 (주)**: 「영어 topic: 별칭들. Examples: 예시들.」을 기계적인 틀로 만든다.
  - 영어 topic만 손으로 옮겼다(`run_interest.py` `TOPIC_EN`).
  - `not` 낱말은 넣지 않는다. 의미 검색은 부정을 못 다루기 때문이다.
- **한국어 (보조)**: topic을 그대로 쓴다(예: 「하이브리드·희소 검색」). 언어 효과를 보려는 것이다.
- 질의 글은 결과를 보고 고치지 않는다.

## 4. 전략 5개 (사용자 결정 11/12)

| 이름 | 무엇 | 설정 |
|---|---|---|
| kw | 지금 제품의 키워드 매칭 | `keyword_match.score_item(kw+aliases)`. 관심사마다 그 관심사 점수(우선순위 가중, 그 관심사의 `not` 감점) 내림차순, 동점은 전체 점수 → id. 질의 글을 쓰지 않아 영어·한국어 순위가 같다 |
| s2 | BM25 | Arena S2 그대로 (ES 9.5.4, `text` nori mixed + `text.en` english 두 필드, k1 1.2 · b 0.75) |
| s4 | **시멘틱 서치** | Arena S4 그대로 (ES kNN, BGE-M3 dense, `hnsw` float, m 16, ef_construction 100, num_candidates 200, cosine) |
| s3a.ko | KURE-Sparse | Arena S3a.ko 그대로 (KURE-Sparse-nano, revision 고정) |
| s6 | 하이브리드 + 리랭커 | Arena S6: S5a(BM25 + S4 RRF, k 60) 상위 문서를 bge-reranker-v2-m3로 재정렬. **재정렬 깊이만 Arena 50 → 100** |

- s6 깊이를 바꾼 이유: 50이면 상위 30 문서 집합이 1단계 상위 50 안에서만 바뀐다. 지표가 recall@30이라, 재정렬이 집합을 바꿀 여지를 둔다.
- 순위 길이는 문서 30개, 청크는 200개까지 받는다.

## 5. 정답 (판정)

- **풀**: 관심사마다 **영어 질의 5전략 상위 30의 합집합**. 한국어 질의 결과는 풀에 넣지 않는다.
- **판정자**: Claude Sonnet 5.5, `claude -p`(구독, API 키 제거).
  - 관심사마다 한 세션이다. 풀이 100건을 넘으면 나눈다.
  - 전략은 가리고, 문서 순서는 시드로 섞는다(시드 20261112).
  - 문서마다 제목, 출처, 본문 앞 800자를 보인다.
  - 검색 전략에는 LLM이 없다. 그래서 판정자가 Claude여도 같은 모델이 판정하고 채점하는 문제가 없다. 2단계(LLM 판정)를 잴 때는 따로 다룬다.
- **등급** (관심사 정의 = topic, description, aliases, examples, not을 판정자에게 보인다):
  - **2**: 이 관심사에 속하는 특정한 새 도구·모델·라이브러리·기법·논문·벤치마크(출시, 공개, 큰 업데이트)를 다룬다. 실험 후보가 될 수 있는 것.
  - **1**: 이 관심사가 주제지만 특정한 새것은 아니다(토론, 질문, 경험담, 아는 것에 대한 튜토리얼, 일반 소식).
  - **0**: 이 관심사가 주제가 아니다(지나가는 언급, `not`에 해당, 무관).
- **사람 확인** (사용자, 거부권 방식): 판정자의 값을 보이고, 사용자가 뒤집은 것만 바꾼다.
  - 한 전략만 상위 30에 올린 문서 중 판정이 1 이상인 것 **전부**. 전략 간 승부를 가르는 쌍이다.
  - 판정이 0인 것 중 **무작위 30쌍**(시드 20261112). 놓친 정답 비율을 어림한다.
- 확정한 정답을 `eval/interest/gold-w46.json`으로 얼린다. 얼린 뒤에는 결과를 보고 고치지 않는다.
- **변경 (2026-11-12, 채점 결과 0건 — 사람 확인을 다 하지 못함)**: 판정은 Sonnet 14세션으로 1,024쌍을 매겼다(2 = 186, 1 = 197, 0 = 641).
  - 사람 확인 대상은 148건이었다(한 전략만 찾은 정답 118 + 0 표본 30). 확인 페이지(아티팩트, 카드마다 Sonnet 값을 미리 골라 둠)로 넘겼다.
  - 사용자는 「너무 많긴 한데 얼추 맞을 거 같긴 하네」라며 훑어보았고, **바꾼 값은 0건**이다. 148건을 다 보지는 않았다.
  - 그래서 정답은 **Sonnet 판정 그대로**다. 위 「사람 확인」은 이번 판에 사실상 하지 않은 것으로 적는다.
  - 판정자 편향을 따로 걸러내지 못했으니, 보조 지표 「등급 2만 recall」을 함께 읽는다. 1과 0을 가르는 경계가 가장 흔들리기 쉽다.
  - 다음 판에서는 확인 대상을 줄인다(예: 한 전략만 찾은 정답 중 무작위 30).
  - 얼린 파일: `gold-w46.json`(sha256 앞 16자리 `cca3e20f88847d75`), 풀 `pool-w46.json`.

## 6. 지표

- **주 지표: recall@30**. 등급 1 이상을 정답으로 친다(뒤에서 LLM이 거르니 주제만 맞아도 모아야 한다). 풀 기준 **상대 recall**이다. 관심사마다 계산해 평균(매크로)을 낸다.
  - 풀에 정답이 0개인 관심사는 평균에서 빼고 개수를 적는다.
- 보조: recall@30(등급 2만) · nDCG@10 · 관심사별 표 · 한국어 질의 recall@30.
  - 한국어 질의는 풀 밖 문서를 미판정으로 두고 judged@30을 같이 적는다.
- 판정 깊이 = 순위 깊이 = 30이다.
  - 변경 (2026-11-12, 결과 0건): 사용자와 처음 이야기한 것은 recall@50이었다. 풀 깊이(30)와 지표 깊이가 다르면 31~50위 문서가 판정되지 않아, 등록 전에 30으로 맞췄다.
- 관심사 14개, 한 주(W46)만 본다. 그래서 결론은 **방향성**까지만 말한다(규율 5). 차이는 관심사별 짝 비교(같은 관심사에서 전략 A − 전략 B)로 보고, bootstrap 95% CI(10,000회, 시드 20261112)를 곁들인다(판정에는 쓰지 않는다).

## 7. 사용자 예측 (2026-11-12, 결과 0건)

> 「예측은 시멘틱 서치가 제일 높을듯 다음으로 KURE 일듯?」

- 예측: **recall@30(영어, 매크로) 1등 = s4 시멘틱 서치, 2등 = s3a.ko KURE-Sparse.**
- 판정: 1·2등이 그대로면 적중이다. 1등만 맞으면 「1등 적중」으로 따로 적는다. 평균 차이가 0.02 안이면 동률로 보고 순위를 함께 적는다.
- Claude 쪽 예측은 등록하지 않는다(learning-mode — 예측 격자는 사용자 가설을 재는 것).

## 8. 한계

- 상대 recall이다. 다섯 전략 모두 상위 30에 못 올린 정답은 보이지 않는다.
- 판정자는 Claude 한 번이다. 사람은 승부를 가르는 쌍과 0 표본만 본다.
- 한 주, 관심사 14개다. 커뮤니티 글 위주라 Arena(문서·릴리스 노트)와 과제가 다르다.
- 판정 세션 수는 풀 크기를 본 뒤 정확히 적고 시작한다(어림 15~20세션).
