# ES kNN 결정론 실험 (2026-10-29, HYO-155 후속)

`test-final-2026-10-29.md` 「변경」의 후속. test 채점 실행에서 S4 · S4.bbq · S4.int8 순위가 rank-only 실행과 달랐다 — 원인을 쟀다. 레포 코드는 바꾸지 않았다(실험 스크립트만).

## 방법

- test 36질의 · 질의 벡터는 질의마다 한 번 인코딩해 고정(같은 프로세스에서 두 번 인코딩한 차이 = 0.0, 네 변형 모두)
- 설정마다 인덱스를 하네스와 같게(DELETE → PUT → bulk 100 → refresh) **3번 새로 만듦**, 첫 인덱스엔 같은 질의 두 번 · forcemerge 1세그먼트로 **2번** 더
- 기준: 캐시된 청크 임베딩으로 numpy 정확 코사인 top-100 청크 → 문서 상위 10
- 인덱스 이름 `…-knndet`(하네스 인덱스와 겹치지 않음), 끝나고 지움. Neo4j 무관

세그먼트는 매번 4개, 건수 나뉨이 다르다(예: S4 [900, 1000, 1100, 856] / [800, 1043, 1043, 970]).

## 결론

- **확인**: 질의 시점은 결정론이다. 흔들림은 **색인을 새로 만들 때**(세그먼트 나뉨이 매번 다름) 생긴다. 거의 다 **S4.int8** — 상위 10 집합은 거의 같고(35/36) 순서가 바뀐다
- **추정(확인 안 함)**: int8은 세그먼트마다 양자화 구간이 정해지고 재채점 없이 양자화 점수로 순위를 매긴다. bbq는 float 재채점(oversample 3.0)이라 거의 안 흔들린다. 하네스 실행에서 S4·S4.bbq에 보인 1e-7 수준 점수 차는 이 실험(한 프로세스, 질의 벡터 고정)에서 재현되지 않았다 — 프로세스가 다르면 GPU 질의 인코딩이 미세하게 다를 가능성
- **forcemerge 1세그먼트는 처방이 아니다** — 결정론도 안 생기고 정확 검색에서 더 멀어진다(추정: 세그먼트 하나면 `num_candidates` 200을 한 번만 탐색 — 지금은 세그먼트 4 × 200)
- dev 재현(P3)이 같았던 이유(추정): nDCG를 소수 셋째 자리까지 비교했고, int8의 순서 흔들림은 상위 10 집합을 거의 안 바꿔 평균이 같았다(test에서도 S4.int8 차이 이동 최대 0.016)

## 처방 후보 (사용자 결정)

- **지금처럼 「판정한 그 순위(rank-only)로 채점」 + int8 흔들림을 한계로 적기** — 추천. S4 float · kure는 정확 검색과 같고 다시 만들어도 상위 20까지 같다
- S4.int8에 재채점(`rescore_vector`) — bbq 결과로 보아 효과 있을 것(추정, 시험 안 함). 등록된 「int8은 재채점 없음」을 바꾸므로 새 변형(`S4.int8.v2`)으로 등록해야 한다
- 세그먼트 나뉨 고정(refresh_interval −1 + 한 번 flush 등) — 시험 안 함, 결정론 보장 근거 없음
