# judge 루브릭 채점 (HYO-20, 틈 ⑥)

`run_judge.py` — 케이스의 `judge` 루브릭(관찰 가능한 Y/N + pass/fail 앵커, `eval/cases/*.jsonl`)을 채점한다. 처음(HYO-20)엔 **평가 대상과 다른 회사 모델**이 원칙이었다 — 2026-11-21부터 기본 judge는 그 예외다 (아래).

- 모델: **Claude Sonnet 5.5, 구독 `claude -p`** (`claude-sonnet-5-5`, effort medium, 기본 `--judge claude`) — 2026-11-21부터 (HYO-210, 아래 「결과 — 2026-11-21」)
  - 처음(HYO-20)엔 **GPT-6 Sol** (`codex exec -m gpt-6-sol -s read-only`, ChatGPT 구독 — Sonnet급 판단은 Sol, 사용자 2026-09-30, adr 0008). 그 구독이 11월 말에 끝나고 유료 API는 상시로 쓰지 않아서, 남는 구독인 Claude로 바꿨다 — **평가 대상과 같은 회사**다
  - 다른 회사 judge로 가끔 교차 확인: `--judge gemini`(Gemini 4 Carbon API — `.env`의 `GEMINI_API_KEY`, 시험용 선불 크레딧이 있을 때) · `--judge codex`(구독이 살아 있을 때)
- judge는 문구와 표본만 받는다 — 파일·웹을 더 보지 않는다 (codex는 빈 디렉터리에 `prompt.md`·`items.json`만, Claude · Gemini는 한 번의 요청에 둘 다. Claude는 도구 없음 · API 키를 지워 구독으로만)
- **음성 대조**: 루브릭의 fail 앵커로 만든 표본을 섞는다 — judge가 그것만 N으로 골라야 무는 것이다 (CLAUDE.md 규율 3)
- **k회 반복**: 같은 표본에 다른 답 = 루브릭 버그 (eval-precondition 항목 4 — 판정 분산은 평균 내지 않고 없앤다)
