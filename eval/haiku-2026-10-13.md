**① 환경 결함 (`radar.py`, Windows 한정) — 5건.** Haiku는 `radar.py`를 `python -I`로 불렀다(SKILL.md는 `-I`를 시키지 않는다 — Claude Code 기본 지침의 습관으로 보인다. Sonnet 기준선은 35회 전부 `-I` 없이). `-I`는 `PYTHONUTF8`를 무시하므로 Windows에서 stdin이 cp949 + `surrogateescape`로 읽힌다 → `decide` 입력의 한국어 `reason`이 깨진 문자열이 되고, `write_updates`(`--apply`)가 **ADR 파일에 깨진 reason을 쓴 뒤** `out()`에서 `UnicodeEncodeError: surrogates not allowed`로 죽는다. 재현: `printf '{"r":"접근 실패"}' | python -I -c "import sys; print(sys.stdin.encoding, sys.stdin.errors, ascii(sys.stdin.read()))"` → `cp949 surrogateescape '…\udcec…'`.
- 021·025·026·027: Haiku가 오류를 보고 `decide`를 다시 불러 성공 — 나머지 검사는 전부 통과, `decide 1회` 하나만 실패
- 024: Haiku가 재시도·손 수정 없이 멈추고 `incident`로 보고(깨진 기록 위치·사람이 할 조치까지) — 채점기는 decide 출력이 없어 `adrs_checked: []`를 INV-5 안전 실패로 셌다. 행동 자체는 R8·R9 정신에 맞는다
- 영향 범위: 스킬을 **Windows에서 `-I`로** 부를 때만. routine(클라우드 Linux)·제품·데스크톱(`PYTHONIOENCODING=utf-8`, `-I` 없음)은 해당 없음 — 데모 무관

**② 모델 실패 — 1건.** JHS-051(D06 LEANN v0.5.0): Haiku는 LEANN이 스택에 없다고 먼저 버리고, ADR 0004와 겹친다는 것을 본문에 적고도 `skipped_existing`에 기록하지 않았다. R14는 기존 ADR과 겹치는 후보를 `skipped_existing`으로 남기라고 한다 — 걸러내는 순서(스택 밖 → 버림)를 먼저 탄 절차 실수.
