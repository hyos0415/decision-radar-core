# 스킬 ↔ 제품 비교를 닫는다 — 합집합 판단 (2026-11-21)

> 기록 2026-11-21 · HYO-226 · 등록 변경은 `docs/design/comparison-protocol.md` §1 · §8 변경 2026-11-21, `docs/design/union-pipeline.md` §8 변경 2026-11-21
> 11/23에 내기로 등록한 합집합 운영 판단(HYO-167, 비교 프로토콜 §8 변경 2026-11-07)을 이틀 당겨 내린 기록이다.

## 결정

| | |
|---|---|
| 합집합 | **합치지 않는다.** 스킬 라이브 검색을 수집 깔때기에 넣지 않는다 — `RADAR_UNION`은 꺼진 채 둔다 |
| 비교 | **닫는다.** 이 날 뒤로 스킬과 제품을 견주는 실행을 새로 하지 않고, 제품 결과를 「스킬 대비」로 말하지 않는다 |
| 스킬 | **얼린다 — tag `skill@v1`(`b9081c7`, 2026-10-01).** 지우지 않는다. 제품 개선을 역수입하지 않는다 |
| 운영 | 제품 하나만 돈다 |

누가: 사용자(레포 주인), 2026-11-21 — Claude의 물음 「HYO-226(스킬 ↔ 제품 비교 닫기)을 진행할까요?」에 「진행」.

## 이유

사용자(11/21, 줄임): 「결론은 스킬이 하는 일을 제품에서도 할 수 있게 만든 거고 … 부품들 파이썬 스크립트들을 스킬로도 호출할 수 있는 거 아님? 스킬이랑 비교를 할 이유가 없는 거 아니야? 하나의 통합된 UI에서 볼 수 있느냐 없느냐 차이 아님?」

두 체계가 같은 부품(스크립트)을 부르므로 견줄 것이 남지 않았다는 판단이다. 새 측정 자료를 보고 정한 것이 아니다.

Claude가 덧붙인 해석(사용자 말이 아니다): 남는 실제 차이는 순서와 규칙을 누가 쥐느냐다 — 제품은 코드가 단계를 집행하고, 스킬은 모델이 문서를 읽고 따른다. 이 차이를 스킬과 견줘 잰 자료는 없다.

일정도 이유다: Claude Max가 11/22쯤 끝난다(사용자 「아마도」). 세션이 드는 일을 그 전에 정리한다.

## 본 것

같은 주 재생 W41~W43 (`docs/decisions/replay-W41-W43.md`, HYO-164, 2026-11-14 실행):

| | 건수 |
|---|---|
| 스킬 초안 | 4 |
| 둘 다 | 1 (vLLM 0.31.0) |
| 스킬만 | 3 — 전부 **수집 시점** (FastAPI 0.143.0 · Langfuse 5.0.0 · Anthropic Python SDK 2.0.0 — 그 주 코퍼스엔 없고 다음 주 코퍼스에 있다) |
| 제품만 | 16줄, 서로 다른 항목 12개 |

- 관문이나 모델이 놓쳐서 「스킬만」이 된 항목은 0건이다
- 제품만 12개가 쓸모 있었는지는 재생이 판정하지 않았다(후견지명을 피하려고 사람 라벨을 붙이지 않았다)
- 재생이 읽은 대로 — 스킬에 제품을 더하면 **항목**이 늘고, 제품에 스킬을 더하면 **시점**이 당겨진다(3건을 6일 일찍)

## 보지 않은 것

등록(비교 프로토콜 §8 변경 2026-11-07)은 답을 「같은 순간 짝과 재생 자료로」 내기로 했다. 그 절반 없이 정했다.

- **같은 순간 짝(스킬 그림자, HYO-166)의 출력을 보지 않았다.** 봉인(11/22까지)이 풀리기 전이다. 이 기록을 쓴 세션에서 Claude도 그림자 출력(초안 · transcript)을 열지 않았고 실행 기록(`shadow-skill/index.jsonl`의 성공 여부)만 봤다
- 짝은 등록한 두 주 중 **W47 하나뿐**이다(실행 2026-11-16 11:55, `skill_commit` `b9081c7`). W46은 맥 앱이 꺼져 있어 돌지 않았다(`docs/decisions/real-use-changes.md` 2026-11-16 줄)
- 재생의 「스킬만 = 수집 시점」 가운데 재생 설계(월요일 웹 검색 ↔ 지난 화요일 코퍼스, 6일 차이)가 만든 몫이 얼마인지 — 같은 순간 짝으로 다시 보기로 했던 질문이다. 다시 보지 않았다
- `union-pipeline.md` §7의 문턱(「스킬만 잡은 항목이 거의 없으면 합치지 않는다」)으로 정한 것이 아니다. 재생만 보면 스킬만 잡은 항목은 3건 있었다
- 반대 논거 E(통합 UX가 가치, 판정문 H절)는 여전히 검증하지 않은 채다. 제품 하나만 돌리는 것은 검증 결과가 아니라 운영 선택이다

그림자 자료는 지우지 않는다. 봉인이 풀린 뒤 「둘 다 · 스킬만 · 제품만」으로 **관찰로만** 집계할 수 있고, 그 결과로 이 결정을 되돌리는 문턱은 두지 않는다 — 한 짝 · k=1이라 스모크다.
